SLIDE 3 - PROJECT OVERVIEW

The system addresses three major needs in modern farm operations:
- Farm production planning and operational tracking
- AI-assisted financial planning with scenario analysis
- Voice-first and low-friction data collection for farmers

Key capabilities:
- Guided farm questionnaires through voice or text
- Financial planning with CAPEX, OPEX, ROI, IRR, NPV, and payback calculations
- Support for aquaponic and land-farming workflows
- AI advisor for multilingual guidance
- IoT data ingestion for water quality monitoring
- PDF and Google Sheets export for reporting and collaboration

TRANSCRIPT - Slide 3

The project is designed for practical farm decision support. A farmer can start a guided survey, provide answers by voice or text, and receive a structured financial plan and recommendations. The platform is built to support real operational use, not only academic demonstration, so the system emphasizes validation, clarity, and modular design.

SLIDE 11.1 - PHASE II CHANGES INCORPORATED

Summary of Phase II suggestions and incorporation

- **Sarvam integration:** Added Sarvam LLM (Sarvam-M / Sarvam 30B) as the AI Advisor backend for multilingual advisory and chat features; referenced in frontend dashboard and service layer.
- **Saarika / Sarvam Saarika v2 STT:** Integrated Sarvam Saarika v2 REST API as an additional transcription system used in evaluation runs (compared against faster-whisper). This is available as a selectable evaluation target in the backend eval pipeline.
- **Whisper (faster-whisper) + Web Speech API:** Kept faster-whisper (large-v3) as the primary offline STT option and the browser `Web Speech API` for in-browser capture; both are supported end-to-end (capture → server transcription → post-processing).
- **Voice testing via ngrok:** Added guidance and tooling to use `ngrok` to expose the evaluation endpoint for remote participant recordings; useful for field testing and collecting labeled audio for WER analysis.
- **Evaluation comparisons:** The eval pipeline now supports side-by-side WER runs and CSV export for: faster-whisper (large-v3), Sarvam Saarika v2, and browser-captured transcripts (Web Speech API). Results are accessible via the eval status and results endpoints.

TRANSCRIPT - Slide 11.1

Following Phase II feedback, we expanded the voice stack and evaluation tooling. Sarvam was onboarded for multilingual AI advisory, Saarika (Sarvam's STT) was added to compare against faster-whisper, and the Web Speech API continues to provide lightweight browser capture. We also added ngrok-based remote testing instructions so participants can submit clips from the field and the eval pipeline can produce WER comparisons and CSV exports for analysis.

SLIDE 12 - SECURITY AND RELIABILITY

Implemented safeguards:
- JWT authentication for protected operations
- Password hashing through bcrypt
- Ownership checks on user-bound data
- Rate limiting through SlowAPI
- Graceful database error handling
- Background Whisper model preload without blocking startup
- CORS configuration and gzip compression

Reliability notes:
- Backend starts even when DB connectivity is delayed
- Redis connection lifecycle is managed at app startup and shutdown
- External integrations fail safely with explicit errors

TRANSCRIPT - Slide 12

Security and reliability were treated as core requirements, not optional features. The backend now includes defensive error handling and rate limiting, and the application avoids exposing one user’s session data to another. The startup flow is designed to be resilient even when the database or external services are temporarily unavailable.

SLIDE 14 - CHALLENGES FACED

Major implementation challenges:
- Handling voice input reliably across browsers and devices
- Supporting both aquaponics and land-farming logic in one platform
- Designing financial calculations that are deterministic and explainable
- Integrating AI while keeping core logic auditable
- Managing external services such as Google Sheets and STT safely
- Ensuring session data is isolated per user

TRANSCRIPT - Slide 14

The main challenge was balancing intelligence with reliability. Some features, like crop feasibility and financial outputs, needed to be deterministic. Other features, like AI advice and transcription, needed flexibility. The final implementation separates these concerns so that the system stays understandable and testable.
