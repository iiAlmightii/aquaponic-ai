2.1 Background and Problem Statement
--------------------------------------
Indian agriculture employs over 50% of the workforce yet remains largely
data-poor. Aquaponic farming — integrating fish culture with hydroponics in a
recirculating ecosystem — is an emerging high-value segment but lacks affordable,
accessible planning and monitoring tools tailored to smallholders. Existing
solutions are either enterprise-grade (costly) or generic farm-management tools
that ignore the unique nutrient cycling, stocking density, and dual-revenue
structure (fish + crops) of aquaponic systems.

Land-based farmers face an analogous gap: no accessible tool exists that lets a
farmer who is illiterate or semi-literate collect operational data via voice,
instantly compute financial projections, and receive actionable AI advice in
their local language.

AgriSense was built to bridge this gap: a full-stack web application offering
voice-first guided surveys, multi-scenario financial modelling (CAPEX / OPEX /
ROI / IRR / NPV), water-quality IoT monitoring, real-time crop market price
integration, a knowledge-base-driven crop feasibility engine, and an LLM-powered
AI advisor — all accessible from any device with a browser.

2.2 Objectives
---------------
1. Build a voice-driven questionnaire engine (aquaponic + land-farm variants)
   that guides farmers through data collection using speech input.
2. Compute financial projections: CAPEX, OPEX, monthly cash flows, ROI, IRR,
   NPV, break-even, and payback period under three scenarios (base / pessimistic
   -20% / optimistic +20%).
3. Integrate real-time commodity market price data (data.gov.in Agmarknet API)
   for crop revenue estimation.
4. Provide a crop feasibility engine using a JSON knowledge base sourced from
   FAO and ICAR-CIFA literature.
5. Enable IoT water-quality data ingestion (pH, dissolved oxygen, temperature,
   ammonia, nitrite, nitrate, turbidity, TDS).
6. Deliver AI advisory chat powered by the Sarvam-M multilingual LLM.
7. Offer Google Sheets export for financial data.
8. Generate downloadable PDF financial reports via ReportLab.
9. Support Supabase cloud PostgreSQL and local Docker PostgreSQL deployments.
10. Provide a responsive React 18 SPA with role-based access (admin / farmer /
    viewer).

2.3 Scope
----------
- Two survey flows: Aquaponic Voice Survey and Land-Farm Voice Survey.
- Financial calculation for both farm types.
- IoT ingestion endpoint for water sensors.
- AI Advisor (chat) using Sarvam multilingual LLM.
- Crop intelligence: feasibility evaluation against area, temperature, pH, and
  grow system.
- Market price fetching with 6-hour cache and fallback hardcoded Indian prices.
- Report generation (PDF) and historical session management.
- Google Sheets financial sync.
- Evaluation harness for STT A/B testing (enabled via EVAL_MODE=true).
- Not in scope: mobile app, offline mode, regional-language TTS.

4.1 Domain Background
----------------------
Aquaponics is a production system that couples aquaculture (raising fish) with
hydroponics (growing plants in water) in a symbiotic environment. Fish waste
provides organic nutrients for plant growth; plants filter water for fish.
Global aquaponics market size was USD 1.5 billion in 2022 and is projected to
grow at 12.5% CAGR through 2030 (Grand View Research).

Indian agriculture GDP contribution: ~18% (2023-24). Number of farmers with
smartphone access has crossed 60% (TRAI 2024). Yet fewer than 5% use any
digital farm-management tool (NABARD 2023).

4.2 Existing Systems and Their Limitations
-------------------------------------------
| System            | Limitation                                          |
|-------------------|-----------------------------------------------------|
| FarmLogs / Granular| US/EU centric, not suited for aquaponics            |
| AquaManager Pro   | Desktop-only, no financial modelling                |
| Cropin            | Enterprise SaaS, cost-prohibitive for smallholders  |
| Government portals| Static, no voice input, no AI advisory              |
| Google Sheets     | Manual, no guided survey, no automatic computations |

4.3 Key Technologies Reviewed
-------------------------------
- Speech-to-Text: OpenAI Whisper (faster-whisper CTranslate2 backend) vs.
  Google Web Speech API. Whisper chosen for offline capability and accuracy
  on Indian-accented speech.
- LLM advisory: OpenAI GPT-4, Anthropic Claude, Sarvam-M (chosen for
  multilingual Indian-language support at lower cost).
- Financial modelling algorithms: NPV, IRR (Newton-Raphson iteration),
  Payback Period, ROI, Break-Even analysis.
- Database: PostgreSQL 16 with JSONB for flexible session context storage
  vs. MongoDB (relational integrity preferred for financial data).
- Frontend: React 18 + Zustand vs. Vue 3 / SvelteKit (React chosen for
  component ecosystem; Zustand for lightweight state management).

7.2 Key Algorithms and Module Logic
-------------------------------------

A. Questionnaire Engine (services/questionnaire_engine.py)
   - Question bank of ~30 questions with id, text, type (text/number/select/
     multiselect/boolean/date), options, unit, min/max value, category.
   - Categories: setup, fish, crops, financials, market, planning.
   - Engine.next_question(context) → returns next unanswered required question.
   - Engine.parse_answer(question, raw_text) → validates, normalises, returns
     typed value. Number parsing resolves spoken words (e.g. "fifty thousand" →
     50000) and STT homophones ("too" → 2, "for" → 4).
   - Engine.is_complete(context) → True when all required questions answered.
   - Session context_data JSONB accumulates {answers: {q_id: value}}.

B. Financial Calculator (services/financial_service.py)
   - FinancialInputs dataclass: capex fields, monthly opex fields,
     monthly revenue fields, horizon_months, discount_rate (8% default).
   - Computed properties: total_capex, monthly_opex, monthly_revenue, monthly_net.
   - FinancialService.calculate(inputs) → FinancialMetrics:
     * annual_opex = monthly_opex × 12
     * annual_revenue = monthly_revenue × 12
     * gross_profit = annual_revenue − annual_opex
     * net_profit = gross_profit (pre-tax in current version)
     * roi_percent = (net_profit / total_capex) × 100
     * payback_period_months: months until cumulative net cash flow ≥ 0
     * break_even_month: first month where cumulative cash flow turns positive
     * NPV: sum of discounted monthly net cash flows − total_capex
     * IRR: Newton-Raphson iteration on monthly cash flows
     * Per-sqm metrics: revenue_per_sqm, profit_per_sqm, capex_per_sqm
     * Cost share: feed%, labor%, utilities%, maintenance% of total opex
     * Revenue share: fish%, crop%, other% of total revenue
   - Three scenarios stored as JSONB:
     * base: calculated as-is
     * pessimistic: revenue × 0.80 (−20%)
     * optimistic: revenue × 1.20 (+20%)

C. Land Financial Service (services/land_financial_service.py)
   - compute_land_financials(context) uses survey answers to compute:
     * Labor cost = workers × salary/month × 12
     * Electricity = units × cost/unit × 12
     * Seed cost = seed_cost/cycle × total_cycles_per_year
     * Revenue per crop = yield_kg × price/kg × (1 − spoilage%)
     * Calculates ROI, payback, break-even for land farms.
   - Returns CSV-exportable dict for Google Sheets sync.

D. Voice Interpretation (services/voice_interpretation.py)
   - FILLER_NOISE_RE strips um/uh/like/you-know fillers from STT output.
   - extract_spoken_number(): resolves Indian number words (lakh, crore),
     homophones (won=1, to=2, for=4, tree=3, ate=8), compound forms
     ("twenty three thousand" → 23000).
   - Confidence score from Whisper segments used to flag low-confidence answers
     for user confirmation prompt in the UI.

E. Land Farm Survey Engine (services/land_farm_survey_engine.py)
   - State machine with prompts: farm details → crop list → per-crop details
     (area, yield, cycles/year, price) → costs (labor, electricity, maintenance,
     land rent, seed, pesticide, fuel, transport, fertilizer, water) →
     CAPEX (machines, setup cost) → financial horizon.
   - _is_valid_crop_name(): rejects STT noise ("thanks for watching",
     "like and subscribe") from crop name answers.
   - _clean_crop_name(): strips punctuation, deduplicates repeated words.
   - parse_prompt_answer(prompt, text): type-aware parsing using
     _extract_number() for number prompts.

F. Crop Intelligence Service (services/crop_intelligence_service.py)
   - Loads backend/data/crop_knowledge_base.json (FAO/ICAR-CIFA sourced).
   - evaluate_crop(name, area_m2, temperature_c, ph, system_type):
     * Checks minimum area and optimal area thresholds.
     * Checks temperature range (min/max from knowledge base).
     * Checks pH tolerance range.
     * Checks grow system compatibility (nft / dwc / media_bed / raft).
     * Returns: feasibility (feasible | challenging | not_feasible),
                reasons[], warnings[], suggestions[].

G. Market Price Service (services/land_market_price_service.py)
   - Fetch flow: in-memory cache (6-hour TTL) → data.gov.in Agmarknet API
     → hardcoded India fallback prices (Agmarknet FY 2024-25 averages).
   - API query progressively broadens filters:
     Step 1: exact state + district + market_name
     Step 2: state + district only
     Step 3: state only
     Step 4: all-India (no filter)
   - Price conversion: Agmarknet prices are in ₹/quintal; service converts
     to ₹/kg by dividing by 100.
   - Returns: PriceResult(price_per_kg, record_count, cache_hit, source).
   - INDIA_FALLBACK_PRICES dict covers 60+ common crops.

H. Audio Transcription (routers/audio.py)
   - Uses faster-whisper (CTranslate2 backend of OpenAI Whisper).
   - Model: large-v3 by default (configurable via FASTER_WHISPER_MODEL env var).
   - Device: cpu by default; set FASTER_WHISPER_DEVICE=cuda for GPU.
   - Model is lazily initialised on first request and cached in-process.
   - Background preload at startup (asyncio.create_task) reduces first-request
     latency.
   - Supports: .webm, .wav, .mp3, .m4a, .mp4, .ogg, .flac input formats.
   - Segments with confidence < 0.6 are flagged; frontend shows confirmation.

I. AI Advisor (routers/ai_advisor.py + services/sarvam_llm_service.py)
   - Chat endpoint: POST /ai/chat {message, session_id (optional)}
   - Routed to SarvamLLMService using the sarvam-m model (Sarvam 30B).
   - Requires SARVAM_API_KEY in environment.
   - Supports Indian language queries (Hindi, Kannada, Telugu, Tamil, etc.).
   - Falls back gracefully to 503 if API key not configured.

J. Report Generation (routers/report.py)
   - PDF generated using ReportLab (BytesIO streamed response).
   - Report sections: farm summary, question-answer log, financial metrics,
     cash flow table, scenario comparison, AI recommendations.
   - GET /report/analytics provides aggregated data for charts:
     monthly revenue trend, ROI distribution, crop revenue breakdown.
   - GET /report/dashboard returns lightweight top-sessions summary
     (uses 60-second frontend cache to avoid duplicate calls from
     Dashboard and Analytics mounting simultaneously).

7.4 Voice Survey UX Flow
--------------------------
1. User lands on SurveysHub → clicks "Start Aquaponic Survey" or "Land Farm Survey".
2. AISurvey / LandVoiceSurvey component calls startSession().
3. First question rendered with text + hint.
4. User clicks mic icon → useVoiceRecorder starts Web Speech API listening.
5. Speech → onResult callback → answer text populated in input field.
6. If STT confidence < threshold, yellow "Please confirm" banner shown.
7. User clicks Submit → submitAnswer() → POST /session/answer or /land-survey/answer.
8. Server validates, parses answer (resolve spoken numbers, validate ranges),
   stores in session_answers table, advances current_step in sessions.
9. Next question returned and rendered. Browser TTS reads question aloud.
10. On completion → FinancialCalculator runs → analysis stored.
11. User navigated to Reports to download PDF.

8.3 Notable Implementation Decisions
--------------------------------------
1. JSONB over separate tables for session context: survey answers accumulate
   per-session without requiring schema migration for new questions.
2. Three-scenario financial output stored as JSONB in financial_plans.scenarios:
   allows atomic retrieval of all scenarios in a single query.
3. Dual database support (Supabase / local): on startup, backend detects
   "supabase.com" in DATABASE_URL and skips create_all (schema pre-applied via
   infra/schema.sql). Local postgres runs create_all automatically.
4. Background Whisper preload: asyncio.create_task at startup warms the model
   cache so first-user transcription is not slow.
5. 60-second analytics cache in api.js: Dashboard and Analytics both fetch
   /report/analytics on mount; frontend cache prevents duplicate API calls
   within 60 seconds of each other.
6. Split loading state in Dashboard: farm count and analytics fetch
   independently so the farm card renders immediately while chart data loads.
7. Rate limiting via slowapi: 200 req/min global, 10 req/min for auth — to
   prevent brute-force attacks without a dedicated WAF.
8. Request timing middleware: X-Process-Time header on every response enables
   performance monitoring from browser DevTools.

SECTION 10 — CONCLUSION (Chapter 8)
================================================================================

AgriSense successfully delivered an end-to-end AI-driven farm management and
financial planning platform for both aquaponic and land-based farms. The system
demonstrated that voice-driven data collection — combined with intelligent speech
parsing that resolves Indian spoken numbers, homophones, and filler words — can
meaningfully lower the barrier to digital adoption for semi-literate farmers.

The three-scenario financial model (base / pessimistic / optimistic) with NPV,
IRR, ROI, payback period, and break-even computation provides a rigorous
decision-support tool for new farm investments. Integration with the data.gov.in
Agmarknet API for real-time commodity prices ensures financial projections are
grounded in actual market conditions rather than static assumptions.

The crop feasibility engine, backed by FAO and ICAR-CIFA literature, gives
objective guidance on whether a given crop is viable in a farmer's available
area, temperature zone, and water system type — addressing a critical
information gap for first-time aquaponic entrants.

The platform was validated through comprehensive unit tests covering spoken
number parsing, market price caching, crop feasibility logic, and financial
metric computation. All critical service-layer algorithms are independently
testable without database dependencies.
